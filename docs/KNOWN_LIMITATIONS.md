# Known limitations

- The uploaded source is Mi Remote **7.2.4M / code 6500**. Version 1.4.0 imports every attributable supported raw TV/AC record from its inspected database: 604 profiles / 24,204 command associations. This does not reproduce Mi Remote's complete online catalogue or all of its AC engines. The raw importer separately lists 701 stateful AC definitions requiring encoding; six verified Panasonic216 parameter profiles have an independent encoder. See [TV/AC investigation](TV_AC_COMPATIBILITY_INVESTIGATION.md).
- The user reports Palm Remote 1.3.0 controls their Astro Ultra Box, while the tried Daewoo TV and Panasonic AC selections fail on the same phone where Mi Remote works. Exact appliance models and the working Astro keyset are unknown. The user tried only some Daewoo candidates. The new TV/AC support has not been verified on those appliances. User reports are separate from cloud tests and do not mark every source profile hardware-tested.
- Daewoo retains 13 raw candidates. Source matching-tree order now starts with `xm_1_3399` and `xm_1_3390`; a numbered TV choice on an emitter phone enters guided testing. No named Daewoo TV waveform set was found in the uploaded APK database. Ordering and confirmation improve candidate selection but do not prove which candidate matches the TV.
- Panasonic AC state control covers `137_2587`, `kk_3_137_4646`, `kk_3_137_7406`, `kk_3_137_7790`, `kk_3_137_7791` and `kk_3_137_7793`. Settings are limited to source-supported modes, 16–30 °C and per-profile fan/swing mappings. Auto operating mode is excluded. The last profile uses a power toggle, so the app cannot label its actual on/off state. Other Panasonic families and other vendors' stateful formats are not implemented by this encoder.
- Raw AC/fan profiles replay fixed captures; a command may set several properties together. The independent Panasonic encoder prepares requested settings, not readings from the appliance. No path reads or synchronizes appliance state after another remote changes it. Editing AC settings, navigating or restoring a saved profile sends nothing automatically.
- **IR ready** confirms an Android consumer IR emitter was detected; it does not prove emission or appliance response. Carrier support may remain unknown. A complete valid set of reported ranges can reject an unsupported frequency; optional range-query failure does not cause carrier substitution. **IR check unavailable** reports failed detection, and **Check IR** sends no signal or adds hardware.
- Android 6.0 or newer only. Most phones lack a consumer IR emitter. No iPhone app, external USB/Bluetooth emitter, Wi-Fi IR hub or RF hub is implemented.
- The raw catalogue combines unchanged GitHub Mi v2.1 data (3,706 profiles / 140,949 associations), Astro public service data (five / 216), and uploaded-APK raw data (604 / 24,204). These are snapshots, not coverage of every model or region. Source IDs are code-set identities rather than verified retail-model names. Duplicate waveforms and separate source associations remain distinct.
- Source category labels can be inaccurate. The Aite keyset `kk_3_1877_4562` is categorized as AC upstream but contains decoder-style channel, EPG and digit controls. Retaining that source classification is not evidence of AC compatibility.
- No NJOI-labelled, PRISM+ or PrismPlus profile is included. Astro's service data does not label Ultra Box or Ulti Box retail models; the user's Ultra Box result does not establish Ulti Box support. Another brand is never relabelled as Astro.
- Raw signals require integer carriers from 20–60 kHz, 3–2,000 positive integer microsecond durations, no duration over one second and no total over 1.9 seconds. Unsupported formats, carriers and empty source responses are excluded with reasons. Frames are not truncated, carriers are not guessed, and repeats are not added.
- The generic TV/AC service probes returned HTTP 200 with service status `19` and no data; the public STB endpoint rejected five actual TV/AC IDs with code `-6`. These are service responses, not a cloud network-policy denial. No usable anonymous full TV/AC catalogue route was established; no embedded credentials or signing material are reused.
- The app offers no smartphone JSON import, IR learning, automatic appliance-response detection or Xiaomi database refresh. Earlier non-Mi captures, owner-supplied Astro JSON, learned imports and the native AC engine remain removed. Current saved Mi and Panasonic selections are retained; upgrades from before 1.2.0 remove obsolete IR selections after successful catalogue validation. Wi-Fi metadata and encrypted credentials are preserved.
- Samsung SmartThings needs existing manufacturer authorization, an appropriate token and internet. Tokens expire. LG pairing uses legacy port-3000 SSAP on a trusted private LAN; secure-only sets require another implementation and wake behavior varies by model.
- Development signing only. Production store signing, Play publishing and iOS are separate tasks. The UI is English; Bahasa Malaysia translation is not included.
